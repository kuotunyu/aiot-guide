# AIoT 導讀：章節內容規格

## 這個網站是什麼
公開、非官方的學習網站，主題是 iPAS「AIoT 應用工程師（初級）」兩個學科的範圍：科一 AIoT 基礎概論（9 項）、科二 物聯網系統與應用（6 項）。

讀者：所有想學 AIoT 或準備這個考試的人。**不能假設**讀者有 AI、程式、電子或網路背景。

不做：倒數、讀書計畫、進度、個人化內容、衝刺語氣。

## 寫作要求
- 正體中文（台灣用語），專有名詞第一次出現時附英文。
- 用第三人稱或中性語氣講內容。可以用「你」指一般讀者，但不可寫成對某位特定學生說話（不可有「你有資料背景」「你熟 AI」「抱佛腳」「剩幾天」）。
- 不要太簡陋也不要太冗長：主文（各節 body 與 after）約 2,000 字以內；整章含表格、例題、實驗與自我檢查，章首顯示約 25–40 分鐘（build.py 的 minutes() 計算），超過先刪減，不要靠把表格收進 more 來壓時間。一節 2–5 個短段落。寧可用表格與圖，不堆文字。
- 新名詞當場用一句白話解釋。類比用生活例子（水管、門牌、郵局）。AI／軟體類比只放進 `bridge` 欄位，主文不依賴它。
- 內容要能獨立當學習材料讀，說清楚「它是什麼、為什麼這樣設計、怎麼選」，同時涵蓋應考會用到的名詞、比較與計算。
- 不寫出題頻率或押題（不可有「考題九成」「出題最多」「常考第一名」「考古題出現 N 次」）。應考提醒只放在 `pitfalls`，寫成「容易混淆的地方」。

## 正確性
- 依據順序：標準與原廠規格的通行事實、官方學習指引、既有教材。數字標「典型」。不確定就不寫。
- 官方指引與通行事實衝突時，主文寫正確事實；`pitfalls` 事實放前面，句尾加短標記「（指引 p.N 寫成 X）」或「（指引 p.N 寫法相反）」。頁面會自動說明這個標記。只是名稱或慣例不同的不加標記，寫成具體一句（例如「題目會指定用 2ⁿ 或 2ⁿ－1」）；沒有頁碼的教材說法差異，留一句「考題可能採教材說法」。
- 已知要處理的例子：應變規拉伸時電阻增加（指引 PDF 第 134、141 頁寫反）；Google Cloud IoT Core 已於 2023 年停止服務；HTTP/1.1 預設持久連線；MTConnect 的 Adapter 不一定輸出 XML。

## 著作權（嚴格）
- **不可**放入歷屆試題原文，也不可只換幾個字改寫。例題要自己設計新情境與新數字。
- **不可**大段照抄官方學習指引；用自己的句子重寫，不引用超過 15 字的連續原文。
- 不可提及任何個人資料。

## SVG 規格
- 開頭 `<svg viewBox="0 0 600 H" xmlns="http://www.w3.org/2000/svg" role="img" aria-label="一句描述">`，H 120–440，根元素不設 width/height。
- 不寫任何顏色值、`style=`、`fill="`、`stroke="`。只用 class：形狀 `box acc ok bad warn soft`；線 `ln la dash`；文字 `t tb ts th tc ta`；箭頭 `mk`。（`t` 16px、`tb` 粗體、`ts` 小字 15px、`th` 18px 標題、`tc` 置中、`ta` 主色）
- 箭頭 marker id 必須全站唯一：`<id>-<節序>-arr`，`viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse"`，內含 `<path d="M0,0 L10,5 L0,10 z" class="mk"/>`。
- 只用 rect、circle、ellipse、line、polyline、polygon、path、text、tspan、g、defs、marker。
- 文字不可出界、重疊或超出方框（中文字寬約等於字級）。
- 新畫的方框圓角用 `rx="6"`（小標籤、色塊 4）；膠囊、圓點等形狀照形狀需要。既有的圖不為統一圓角重畫。
- 圖要傳達結構，不當裝飾。圖中文字同樣不可有出題頻率或個人化語氣。

## 逐步圖與第二張圖
- **逐步圖**：同一張 SVG 用「上一步／下一步」切換 3–8 個狀態，用在先後、因果、狀態變化。只在三種情況用它：時間順序、一步步改變的狀態、拆開後才看得懂的過程。要並排比較或一眼看全貌的，用靜態圖。
  - 在節上加 `"steps": ["每一步一句說明", ...]` 與 `"start": n`（沒有 JS 與列印時顯示第 n 步，選最能代表全貌的一步）。
  - SVG 裡只在某幾步出現的圖形加 `data-s="2 3"`（可放在 `<g>` 上）；沒有 data-s 的永遠顯示。步數 = steps 的長度，最多 12。
  - 每步說明一句話，寫「這一步看到什麼、代表什麼」；不要和 caption 重複。
  - 範本：`content/s1-23.json` 的 network-layers。
- **第二張圖**：一節需要多一張圖時，用 `"figs": [{"pos": "...", "svg": "...", "caption": "...", "steps": [...], "start": n}]`。`pos` 決定位置：`after-predict`（先想一想之後、正文之前）、`after-body`（正文之後、實驗之前）、`after-after`（after 之後、主圖之前）、`end`（主圖之後，預設）。圖不可以排在 predict 前面洩漏答案。
- **手機可讀**：手機上章節圖最小寬 480px（約 0.8 倍），比畫面寬時在 `.dgs` 內框裡左右捲動。主要文字用 `t`、`tb`（16px），`ts`（15px）只用在單位、刻度等次要資訊，不再用 13。每張圖約 15 個標籤以內，長說明放 caption 或 steps。
- **配色語意**：`ok／bad／warn` 只表示對錯與警示；中性分類用 `box／soft／acc`；`la` 實線是主要路徑，`ln dash` 是控制或回程。
- **手機直式圖**：左右滑動會切斷理解的圖（流程、時序、分層、對照）可以在 `svg` 旁加 `svgm`，把同一批節點與文字重新排成直向；座標圖、波形等不適合重畫的維持左右滑動。figs 的項目也可以加 `svgm`。
  - 開頭 `<svg viewBox="0 0 360 H" xmlns="http://www.w3.org/2000/svg" role="img" aria-label="...">`，H 200–760（375 寬時約 766px 高，一屏放得下）。其餘規則同桌機版：只用 class 上色、允許的標籤，字只用 text 16、.ts 15、.th 18。
  - 節點與文字和原圖相同，不新增內容；caption、steps、start、loop 兩張圖共用。每行最多約 20 個全形字，標籤約 15 個以內；長標籤換兩行放在箭頭上方。
  - 逐步圖：兩張圖的 data-s 用到的步數集合必須相同。loop：兩張都要有 lp-move／lp-still，svgm 的 keyframes 與 class 用 `lp-m-` 開頭，不可和桌機版同名（svg 裡的 `<style>` 全頁共用）。
  - id（含 marker）用 `<桌機 id 前綴>-m-...`，例如桌機 `s1-22-6-arr2` 對 `s1-22-6-m-arr2`；全站所有 svg id 唯一。
  - 每張 svgm 不大於桌機版的 1.1 倍；一頁因手機圖增加不超過 60KB（build 結尾印出各頁增量）。速查頁重用章節圖時自動帶 svgm。
  - 範本：`content/s1-22.json` mqtt 節 figs[1]（MQTT 生命週期，6 步時序圖：三條生命線 x≈50／180／310，訊息標籤換兩行放在箭頭上方，下方兩格改上下排）。
  - 檢查：verify.js 在 375 寬（縮放 ≥0.95）、320 寬（≥0.8）逐步檢查可見的 .v-m，1280 寬檢查 .v-d。
- **檢查**：`node scripts/figure-shots.js <頁>.html <節 id> <輸出資料夾>` 會截下每一步在桌機、手機、淺色、深色的樣子，交付前要逐張看過。

## 循環小動畫
- 只用在「流動、週期、時間差」：靜止看不出、但動起來一眼就懂的概念（例如封包排隊、輪子在閃光下倒轉）。靜止就看得懂的不要動。每支都要取代一張靜態圖或一段文字，不另外加。
- 寫法：在節或 figs 項目加 `"loop": true`，svg 裡固定兩個圖層：`<g class="lp-move">` 放會動的元素，`<g class="lp-still">` 放靜止版要補的元素（例如掉落的紅點、排好隊的點）。兩層共用同一張底圖（底圖放在兩層之外）。
- 動畫寫在 svg 裡的 `<style>`：只能有 `.lp-` 開頭的 class 與 `@keyframes lp-` 開頭的動畫，只改 `transform`、`opacity`；不可寫任何顏色（顏色仍用 box acc ok bad warn soft 等 class）。同一張圖所有元素共用一個週期（3–6 秒；逐站走流程的圖每站停約 1.2 秒，可放寬到 10 秒），相位用負的 `animation-delay` 錯開；要跳格用 `steps(n)`。
- 靜止版（讀者設定減少動態效果、沒有 JS、列印、截圖的 -still）必須自己就看得懂、能答題；caption 寫成對靜止版也成立的句子。
- 動畫只在捲到畫面內時播放；點圖不放大。
- 可讀性：圓點半徑至少 6（viewBox 單位），會動的標籤不小於 `t`，不可蓋住方塊裡的文字。
- 檢查：`node scripts/figure-shots.js` 會截四個時間點（-a1～-a4）與靜止版（-still），都要看過。

## 練習題詳解
練習題答完後，讀者要一眼看懂「我選的為什麼錯、正解為什麼對、下次怎麼認出這種題」。原則是幫讀者快速吸收，不寫成百科；改寫後整題字數持平或更少。以下欄位加在 `questions-<章>.json` 的 `edits` 或 `add` 題目物件裡，build.py 會檢查。
- `w`（改寫時必填）：長度 4 的字串陣列，順序對應原始選項 `o`（不是畫面洗牌後的順序）。每句 6–28 字，說「這個選項為什麼對／錯」。正解那句寫關鍵理由；錯的選項點出錯在哪個觀念（例如「這是拉伸的方向，題目是壓短」）。不要只寫「錯誤」「不正確」，也不要用 A／B／C／D 指代別的選項（選項會洗牌）。作答後每句顯示在對應選項下方。
- `tip`（選填）：一句考場可直接用的解題線索，≤32 字，例如「看到應變規先寫 R＝ρL／A，拉長變大、壓短變小」。只在有共通判斷法的題目放（公式、方向、選型、反向題的讀題方法），不要硬湊。
- `e`：核心觀念 1–2 句，≤80 字（有 `w` 的題 build 上限 120 字），不重複選項短評已說的內容。原本的「指引 p.N 寫法不同」之類註記保留。
- `conf`（選填）：題目考的概念屬於 `content/confusables.json` 的某一組時，填那一組的 id。id 是該組的 `"id"` 欄位；沒有 `"id"` 的組，id 就是 `<chapter>-<sec>`（例如 `s2-11-edge-fog-cloud`、`s1-31-accuracy-precision`）。同一節有兩組時，其中一組必須在 confusables.json 寫明 `"id"`（例如 `s1-12-false-alarms`）。解析框底部會出現「易混淆：組名」，連到 `glossary.html#conf-<id>`。
- `fig`（選填）：解析框裡的一張小圖，SVG 字串，顯示在核心觀念 `e` 之後、解題線索之前（學習模式、限時檢討、錯題重做都會出現，可點圖放大）。目的是讓讀者更快懂，不是裝飾。
  - 何時該畫：文字要繞一圈才講得清、但一張圖一眼看懂的題目，例如形變與公式的方向（壓短 → L 變小、A 變大）、訊號或時序的先後、拓樸與資料流向、數值落在哪個區間。純記名詞、定義題、選型對照表能講清楚的不畫。同章已有一模一樣的圖時，用 `sec` 連回去，不再畫一次。
  - 規格同上方〈SVG 規格〉（只用 class 上色、允許的標籤），但開頭是 `<svg viewBox="0 0 W H" xmlns="http://www.w3.org/2000/svg" role="img" aria-label="一句描述">`，W 320–420、H 80–320。解析框裡的圖寬 100%、最大 440px，手機 375px 寬時約 350px（縮放約 0.84），所以文字一律用 `t`／`tb`／`th`（16px 以上），不可用 `ts`。
  - 標籤（不同的文字）最多 6 個；長說明放 `figcap`。
  - 圖裡所有 `id`（含箭頭 marker）以 `q-<題目 id>-` 開頭，例如 `q-reserved-s1-31-1-arr`。整段 SVG ≤ 6 KB。
  - `figcap`（選填）：一句圖說，≤40 字，不重複 `e`。
  - `loop`（選填，只能寫 `true`）：循環小動畫，規則同〈循環小動畫〉（`lp-move`／`lp-still` 兩層、`<style>` 只能有 `.lp-` class 與 `@keyframes lp-`、只動 transform／opacity、靜止版自己就能答題）。只用在「變化過程本身就是考點」的題目（例如取樣太慢時輪子倒轉、佇列塞住），否則畫靜態圖。自訂的 `.lp-` class 與 keyframes 名稱會和同頁其他題共用，取名帶題目特徵且不可和別題重複。
  - build.py 會檢查以上規則；寫完要在練習頁實際作答，看桌機與手機、淺色深色。
- 範例：`questions-s1-31.json` 的 `reserved-s1-31-1`（含 `fig`）、`questions-s2-23.json` 的 `legacy-s2-18`、`questions-s1-11.json` 的 `legacy-s1-6`（反向題）。
- 寫完跑 `python build.py`（no problems）與 `python scripts/question-stats.py`（最後一行顯示有 `w`、`tip` 的題數）。

## 介面規則

改 build.py、site.css、site.js 或介面文字時照這幾條。

- **圓角**：全站只有 `--r:4px`，只給可點的控制項（按鈕、輸入框、選單、chip、選項、導覽連結）。資訊框、卡片、清單列、標示、影片一律直角；時間軸圓點的 50% 是形狀，保留。不寫死 px 圓角。
- **間距**：只用 4／8／12／16／24／32（`--sp1`～`--sp6`）。區塊內 4 或 8；區塊之間 16；節與節 24（保留分隔線）；頁內大段 h2 上方 32，不寫 inline margin。
- **框**：一個內容最多一層框，不框中框。能用分隔線或左側色條就不用整圈框；純說明的群組不加框。
- **字級**：內文桌機 19px、手機 18px。HTML 文字最小 15px，例外只有兩種：上標 sup（最小 13px）和列印。`code` 用 `max(15px,.88em)`。手機不另外縮小輔助字，麵包屑、標籤、朗讀列都一樣。表格桌機 17px，手機 16px 以上。章號不包框、不加底色，用等寬粗體加科目色（首頁清單 22／20px 自成一欄，章首 26px，在標題裡跟標題同大，側欄與名詞／速查章節索引 18px，指引差異 18px）；首頁資料路徑的章號鈕是可點的控制項，等寬粗體 20px（901–1440 為 18px，手機 19px），觸控高 46。頁首導覽桌機 20px、平板 19px、手機 18px 平均撐滿一列，高 44 以上。
- **圖（SVG）**：字級以「畫面上實際大小」為準，也就是 font-size 乘上 getScreenCTM 的縮放比。手機至少 12px（.t／.tb 至少 12.8px），桌機與平板至少 14px。SVG 字只用三級：text 16、.ts 15、.th 18 單位，不再用 13。手機（≤600px）上圖的縮放比不低於 0.8：章節圖 svg 最小寬 480px，放在 `.dgs` 內框裡左右捲動，figcaption、步驟鈕、步驟說明留在內框外。實驗圖的最小寬是 viewBox 寬 ×0.8。圖比內框寬時，上方顯示一行「圖可左右滑動 →」（沿用 .tblhint）。桌機上實驗圖最多放大到 viewBox 寬 ×1.15，避免圖上的字比內文大。圖裡的字不可互相重疊，也不可超出所在方框或 viewBox。要修就改字或把框、viewBox 加大，不可把字縮小。章節圖可以附手機直式版 `svgm`（viewBox `0 0 360 H`，規格見〈手機直式圖〉）：≤600px 時顯示直式版，375 寬時縮放約 1.0，320 寬時不低於 0.8；沒有 svgm 的圖維持 480px 最小寬加左右滑動。放大檢視與列印一律顯示原圖。
- **版面寬度**：正文一行 38–42 個全形字（19px 時欄寬 720–800px）。寬螢幕（≥1441px）不可比 1280 窄：.wrap 1440，正文欄最多 800px，三欄置中。短條目清單（名詞、公式卡、兩科章節清單）的欄寬下限 360px，不讓平板只排一欄、右半邊空白。設定區和作答區同寬，按「開始」後版面不跳。about 等純閱讀頁維持窄欄。
- **節奏**：段距 16（--sp4）；清單項目之間 8（--sp2）；清單上下 12（--sp3）；h3 上 24、下 8。全部只用間距尺度，不再出現 10／22／6／14 這種尺度外的值（控制項內距與手機貼邊用的負邊距除外）。手機貼邊負邊距是 -16px。
- **控制項**：同一組「選一個」的控制項（.seg、.chips、.gview、.theme）高度一致，滑鼠環境 min-height 40px，觸控 44px，字級 16px。手機上 3 欄以下的表格改成「一列一段」（欄名 15px 灰字加值），4 欄以上維持 .wide 橫捲並固定第一欄。每格都很短、手機上排得下的對照表（考試資訊、考試範圍、作答後的各章表現）加 `.facts` 保留表格，避免一列一段反而拉長好幾倍；考試範圍用 rowspan 合併重複的科目與主題。
- **文字**：一個意思只說一次；導覽、標題、控制項已說明的不再加說明句。標籤用名詞或動詞短語，按鈕最多 6 個字。必留：非官方免責聲明（iPAS、經濟部及主辦、承辦、執行單位）、關於頁說明練習題為本站自製（練習頁不再重複）、限時 90 秒是本站估算、「指引 p.N」說明、簡章版本與「請查最新簡章」、隱私承諾。e2e 斷言用到的字串不改。
- **不可退步**：375px 寬沒有橫向捲動；觸控目標不縮小（.btn 44、手機 .say 36、.grid 44）；文字對比淺色深色都 ≥ 4.5:1（22px 以上粗體 ≥ 3:1）；保留 focus-visible 與列印規則；不加陰影、漸層、動畫；顏色只用 site.css 開頭的變數；任何頁面 HTML 最小字 ≥15px（上標除外）；每張 SVG 在 375 與 1280 寬都沒有字疊字，也沒有字超出方框或 viewBox；練習頁 .qnav 觸控高 48；手機與平板的釘住區只有 .tocmenu 一條。

## 手機版與電腦版

同一個網址、同一份內容，依視窗寬度給兩套各自設計的版面（不做兩個網站，不用 UA 偵測）。手機版為單手、直式、零碎時間重新安排，不是電腦版縮小；電腦版為寬螢幕、長時間閱讀與並排查看安排。

- **斷點**：手機 ≤600px（單欄，側邊留白 16px，貼邊負邊距 -16px）；平板 601–900px 的導覽、釘住列、收合、練習底部按鈕列沿用手機版，圖與表格沿用電腦版；電腦 ≥901px，901–1240 雙欄（短標籤目錄＋正文），≥1241 三欄（1241–1440 為 260／748／184，≥1441 為 260／800／240）。正文欄維持 38–42 字一行。
- **只在小螢幕收起**：build 輸出 `details[data-wide]`（章首「有 AI 或軟體背景的話」、章末「本章關鍵字（N 個）」「來源（N 筆）」、練習結果的答對題）。site.js 在載入與跨過 901px 時把 open 設成「是否 ≥901」，不覆寫使用者自己的開闔；連結或 hash 指到裡面時先打開；列印全部打開；朗讀範圍不因收合改變。
- **手機與平板（≤900）**：章節頁只有 .tocmenu 一條釘住列（約 46px，頁首隨頁捲走），選單開頭有「章首」、結尾有上一章／下一章／全部章節；練習的上一題／下一題貼底（觸控高 48，body.reading 時取消）；名詞與速查的章號 chips 單列釘在頁首下、左右捲動。速查一次只顯示一段（公式／指引差異／各章重點，網址 hash 決定哪一段，#guide、#r-<章> 直接打開該段；沒有 JS 與列印時三段全部顯示），章號 chips 與左欄章節索引只在「各章重點」出現。
- **只在手機（≤600）**：章節圖有 `svgm` 就顯示直式版（規格見〈手機直式圖〉），沒有的維持 480px 左右滑動；含 .lab-viz 的實驗改成圖在上、控制項在下、判讀在後；速查卡片裡的直式圖延伸到卡片邊框。觸控螢幕上單行的收合標題（易混淆、看動畫、先想一想）列高 44。
- **電腦（≥901）**：本章目錄 .toc 只顯示標題全形「：」前的主題，完整標題放 title；練習設定與作答共用 760＋280 雙欄（右欄 sticky：題號、剩餘時間、題號格、交卷），按開始後版面不跳；鍵盤 1–4／A–D 選答、← → 換題、Enter 下一題、限時按 G 到題號格（焦點在輸入框時不攔）；≥1241 的名詞與速查改成 200px 左欄章節索引（IntersectionObserver 標目前章）＋內容；exam、about 為 800px 窄欄；速查公式卡最多 2 欄（grid，欄寬下限 360px，逐列閱讀）；滑鼠指到圖或寬表格列時加提示色。圖與表格留在正文欄內全寬，不放到文字旁。
- **窄欄裡的圖**：速查卡片欄寬不足 560px 時（container query），有直式版的圖改顯示直式版，最大 1.1 倍；放大檢視與列印一律顯示原圖。
